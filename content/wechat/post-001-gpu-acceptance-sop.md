# GPU 服务器到货,跑过 gpu-burn 就万事大吉?

> 那些单机 burn-in 永远抓不到的故障

---

## 一个被我们见过太多次的场景

周一早晨,机房里 16 台 H100 服务器到货。运维兄弟按 SOP 跑了一轮:

- `dcgmi diag -r 3` 全绿
- `gpu-burn 7200` 满载两小时,温度功耗正常
- `cuda_memtest` 一遍 HBM 也都过了

签字、入库、上架。下游团队领走 8 台开始训练。

**两周后**,训练框架日志里出现 `XID 79: GPU has fallen off the bus`,凌晨三点上 Llama2-70B 任务时崩了。运维爬起来排查,发现降频:那张卡在 168 小时持续负载下,温度比群均高了 11 ℃。

到货验收没问题,集群上线就掉卡。**这不是个案**。

## 三件套能测到什么,测不到什么

`Field Diag` / `DCGM Diag` / `gpu-burn` 这三件套,是行业里默认的单机 GPU 验收工具。但它们的能力边界很多人没说清楚。

### NVIDIA Field Diag

NVIDIA 官方的现场诊断,RMA 流程的依据。它的**强项**是抓硬件个体的"出厂级"问题——HBM 颗粒、电源模块、PCB 焊接缺陷。

但它有两个隐含前提:
1. 它假设你给它一个**冷启动、空闲**的卡,跑的是固定矩阵的诊断流程
2. 它**不模拟真实负载**——不跑 Llama,不跑 SD,不跑 NCCL

**所以它发现不了**:某张卡在持续高负载下才出现的降频,或者特定 batch size 下才触发的 kernel 异常。

### DCGM Diag

英伟达数据中心级诊断,Level 1–4 强度可选。Level 3/4 比 Field Diag 跑得更久,会做 PCIe 带宽、NVLink、SM 压测、显存压测的组合。

**强项**:行业标准、参数透明、跨版本一致。

**弱项**:跑完总时长一般在 30 分钟左右,**抓不到时间累积型故障**——比如 ECC 错误率每周才出几次,或者一张卡每运行 100 小时降频一次。

### gpu-burn

开源的 matmul 满载压测,跑两小时温度 / 功耗 / ECC / 降频曲线非常直观。**强项**是简单可控,所有数据中心都在用。

**弱项**:它只跑一种 workload(矩阵乘),**不跑通信、不跑训练、不跑量化推理**。

## 三件套永远抓不到的 5 类故障

我们这两年接的单机批量测试案例里,**有 18% 的服务器在三件套全绿之后,被进阶测试抓出问题**。常见的 5 类:

### 1. 持续高负载下的"慢性降频"

某张 H100 在 burn-in 2 小时内表现完美,但跑 24 小时真实训练负载后,核心频率从 1980 MHz 平均降到 1830 MHz,集群级影响 4–8% 的有效算力。

**根因**:风扇控制板老化、机柜气流局部紊流、PSU 在 6 盘满载时电压塌陷。

**怎么测**:24 小时连续真实负载 soak,带温度 / 功耗 / 频率时间序列采集。

### 2. NVLink 对称性异常

8 卡机器,7 个 NVLink 通道带宽达标,1 个低 8%。`gpu-burn` 单卡跑根本看不出来,但是一旦上多机训练,这台机器就成为 NCCL all-reduce 的瓶颈。

**怎么测**:`nvbandwidth` 全对称矩阵,卡间两两实测,看离散程度。

### 3. PCIe 链路速率"假性正常"

`lspci -vvv` 显示 Gen5 x16,但实际数据传输只跑出 Gen4 速率。原因可能是金手指接触不良、主板 BIOS 设置、PCIe 重定时器(retimer)异常。

**怎么测**:`nvbandwidth pcieMatrix` + 持续 8 小时数据传输,看吞吐稳定性。

### 4. HBM ECC 错误的"早期抬头"

新卡 ECC 错误率在出厂时一般 < 1 次/天。但有些卡在到货时已经接近边缘,跑 30 分钟看不出来,跑 72 小时就开始飙升。

**怎么测**:`dcgmi health watch` 全程订阅,72 小时窗口内的 ECC 趋势比单次扫描更有说服力。

### 5. 模型输出"看起来对,但实际退化"

很少有人意识到:**单机的卡可能跑分都正常,但模型输出已经退化**。原因有 firmware bug、kernel 异常、HBM bit flip 等。

`gpu-burn` 是矩阵乘正确性检查,但它**不验证 transformer 的 softmax / attention / layernorm 是否输出和参考一致**。

**怎么测**:跑一遍 MMLU 或 GSM8K 抽测,与同型号参考卡对比分数差。

## 一份真实可落地的单机验收 SOP

把上面所有问题都覆盖,需要的不是更长的 `gpu-burn`,而是一套**多维度、有时间窗、有真实负载**的 SOP。我们在内部 toolkit 里把它叫做 *Single-Node Standard*:

| 维度 | 工具 | 时长 | 抓什么 |
| --- | --- | --- | --- |
| 硬件诊断 | NVIDIA Field Diag + DCGM Diag Level 3 | 30–60 min | 出厂级故障 |
| HBM 深扫 | `cuda_memtest` 全 bit | 30–60 min | 显存颗粒 |
| 满载压测 | `gpu-burn` 8h | 8h | 温度 / 功耗 / ECC 触发 |
| 链路实测 | `nvbandwidth` 全矩阵 + PCIe 持续 | 4h | NVLink 对称 / PCIe 速率 |
| 健康事件 | `dcgmi health watch` 全程 | 全程 | XID / ECC / Thermal 事件 |
| 整机数据 | IPMI / Redfish | 全程 | 风扇 / PSU / 机柜温升 |
| 真实负载 soak | Llama2 / SD / 训练脚本 | **24h+** | 慢性降频 / loss spike |
| 模型质量基线 | MMLU / GSM8K 抽测 | 1–2h | 输出退化 |

**总耗时**:基础流程 48 小时,进阶流程 72 小时。

这是把单机验收**从"看起来没问题"做到"真上线没问题"的最小标准**。

## 对经销商:这套 SOP 怎么变成商业价值

如果你在卖 GPU 服务器,这套 SOP 不只是技术问题,是**商业资产**:

### 1. 把"健康度报告"挂在产品页

每台机器出货前过一遍 SOP,客户能拿到:
- 一份 PDF 报告(封面 + 三支柱结论 + 关键指标)
- 原始 telemetry 数据包(SHA256 留痕)
- 失败件诊断建议

我们接触过的头部经销商,挂了健康度报告之后,**客户验收纠纷下降 70%**。

### 2. 把 RMA 率打下来

到货前抓出的失败件,直接走厂家 RMA。我们给一家月度 ~150 台送测的经销商做过 6 个月统计:

- 累计 880 台送测,初筛失败率 3.2%
- 最终客户上线后 RMA 率从 3.2% 降到 0.8%
- 减少的现场往返成本远超送测费用

### 3. 二手 GPU 服务器交易溢价

二手算力市场最大的痛点是"信任"。一份**第三方中立的健康度报告**,可以让卖家提价 8–15%,买家也愿意先付订金。
